# 统一意见与逐截图修改报告

parent agent 先按共同根因形成统一修改意见，再对每张输入截图写独立、可实施的修改清单。完整链路为：**检测队列 → 单项检测报告 → 统一修改意见 → 每张截图的修改动作 → 整体复核**。单项返回遵循 [统一格式](result-contract.md)。

## 输出文件与唯一事实来源

| 文件                     | 职责                                                         |
| ------------------------ | ------------------------------------------------------------ |
| QUEUE.json               | 当前截图清单、对象与状态、检测点队列和方法计划               |
| `results/<item-id>.json` | 一个检测点在指定范围内的方法记录与结论建议                   |
| `results/<item-id>.md`   | 对应 JSON 的单项人读报告                                     |
| DECISIONS.json           | parent 已采纳结论、统一根因意见及逐截图修改动作              |
| REPORT.md                | 整体判断、统一修改意见、覆盖与缺口，以及单项和逐截图报告入口 |
| pages/INDEX.md           | 每张输入截图一行的实施导航，链接对应 `pages/<frame-id>.md`   |
| `pages/<frame-id>.md`    | 针对一张明确截图的独立修改清单                               |

JSON 是结构化事实源，Markdown 从其展开。parent 改变统一方向或某张截图的动作时先同步 DECISIONS.json，再更新受影响的总报告和截图清单；不能让三处出现不同方案。worker 不修改 DECISIONS.json、REPORT.md 或 pages。

## 统一修改意见

将相同根因、触发条件和修改位置的候选意见合并为 opinion_id。一个 opinion 可以关联多个检测点、多个截图，但每张受影响截图需要自己的 action；不同布局和状态的修改方式分别写出。

合并时区分：

- **已见画面问题**：有具体遮挡、错位、语义缺失等证据。
- **审美调整**：在当前任务和方向下，比例、构图、风格等关系需要改善。
- **参考稿修订**：修订设计依据，不当作当前运行缺陷。
- **待验证**：结论尚不足时写补验，不能生成未经证明的强制修复。

统一意见说明共同问题与设计方向；逐截图 action 说明这个方向在该图中如何落地。一个全局意见可以在某图上只要求保留和复核，不应把所有页面统一放大、缩小或套用相同容器。

## DECISIONS.json

顶层字段固定为 schema_version、review_id、overall、accepted_items、opinions、frame_plans。当前 schema_version 为 `1`。

| 字段           | 内容                                                                                                          |
| -------------- | ------------------------------------------------------------------------------------------------------------- |
| overall        | `{ "conclusion": "整体判断", "preserve": ["需要保护的表达"], "limits": ["未覆盖或待验证范围"] }`              |
| accepted_items | 采纳快照数组，每条为 item_id、item_revision、frame_hashes；与队列及结果当前值一致，不包含失效或尚未接收的结果 |
| opinions       | 统一意见数组，字段见下表                                                                                      |
| frame_plans    | 每张当前输入截图一条计划，不能因无需改动或缺证而省略                                                          |

每条 opinions 记录：

| 字段             | 内容                                                             |
| ---------------- | ---------------------------------------------------------------- |
| opinion_id       | 在本次审核中唯一，如 `F01` 或 `R01`                              |
| title            | 简短说明共同修改目标                                             |
| kind             | `visual_issue`、`aesthetic_adjustment` 或 `reference_revision`   |
| priority         | `first`、`next` 或 `later`，说明本次实施先后，不冒充工程缺陷等级 |
| item_ids         | 支持该意见的已采纳检测项编号                                     |
| root_cause       | 有依据的共同原因；尚未证实时明确为设计归因或待核假设             |
| shared_direction | 统一目标、约束与取舍                                             |
| actions          | 针对实际受影响截图的动作数组                                     |

每条 actions 记录固定包含：

| 字段         | 内容                                                                                     |
| ------------ | ---------------------------------------------------------------------------------------- |
| action_id    | 唯一动作编号，如 `F01-S001`                                                              |
| frame_id     | 一张具体输入截图，不写泛化页面组                                                         |
| object_ids   | 该图中实际涉及的对象编号                                                                 |
| item_ids     | 直接支持本动作的已采纳检测项；非空且为所属 opinion.item_ids 的子集，不照抄其他截图的依据 |
| location     | 可定位的区域、对象及关系，必要时给坐标或截图标记                                         |
| current      | 该图当前看到的具体表现及影响                                                             |
| target       | 改完后希望形成的画面或交互关系                                                           |
| change       | 本图应如何调整，明确改动范围和可保留余地                                                 |
| preserve     | 应保留的具体元素与作用数组                                                               |
| verify       | 用于复核该图及关联状态的检查数组                                                         |
| dependencies | 需要先确定或完成的 opinion_id/action_id 数组；没有则 `[]`                                |

frame_plans 中每条固定为 `{ "frame_id": "S001", "status": "change", "summary": "本图结论", "action_ids": ["F01-S001"], "preserve": [], "pending": [] }`。

status 仅使用：

| 值             | 条件                                                              |
| -------------- | ----------------------------------------------------------------- |
| change         | 本图存在已采纳的具体修改动作；action_ids 不能空                   |
| keep           | 本次没有已确认需改动项；写清保留理由，不等于所有点通过            |
| pending        | 现有证据不足以确定本图改法；pending 写缺什么、如何补验            |
| reference_only | 仅作参考或过程对照；可以列参考修订 action，但不能当作当前实现缺陷 |

截图可能同时有需修改与待验证内容：用 change 并保留 pending 数组。keep 和 pending 不能隐藏已有 action。每条 action 只能归属一个 opinion，frame_plans.action_ids 必须与该 frame_id 的实际动作集合一致，并按实施顺序排列；不得存在孤立动作或指向另一张图的动作。

动作先满足 dependencies，再按 first、next、later 安排无依赖冲突的先后，不按 opinion_id 或 action_id 字典序代替实施顺序。依赖 opinion_id 时明确其所需前置动作；跨图前置在本页单列并链接对应单图报告，不复制成当前截图的动作。发现不存在的依赖或依赖环先解决方案冲突，再生成可实施清单。

action.item_ids 应能直接支持本图、本对象的调整；跨图检测项核对其 finding 实际受影响范围，不能只因截图参与过对比就当作修改依据。原始单项结论与证据不因报告重排而改写。

条目 revision 或截图哈希变化时，其 accepted_items 快照不再有效。parent 移出旧采纳，复核关联意见与动作；失去有效证据支持的 opinion/action 从当前计划移出，在对应 frame_plan.pending 中记录待复核内容和旧编号。若该图没有其他有效动作，status 改为 pending；仍有有效动作时保留 change 并列出缺口。重新核对其余有效证据或取得新结果后再恢复动作，不能只因 item_id 未变就沿用原方案。

## 逐截图索引

pages/INDEX.md 按 page_id、批次和状态组织，但每张截图独立成行。至少包含：

| 截图编号 | 页面与状态                   | 原图路径     | 本图结论                                      | 修改动作                              | 单页报告      |
| -------- | ---------------------------- | ------------ | --------------------------------------------- | ------------------------------------- | ------------- |
| S001     | 填写逻辑页面、批次与截图状态 | 精确文件路径 | change/keep/pending/reference_only 的中文解释 | 关联 action_id，或明确无需改动/待验证 | pages/S001.md |

同一逻辑页面的不同截图可相邻排列，不能折叠成一行“首页同上”。原始截图与逻辑裁剪图分别有入口，注明来源关系、主要审核图及可支持尺度；重复材料不算额外验证。

索引中的修改动作沿用该图 frame_plan.action_ids 的实施顺序。

## 每张截图的修改清单

`pages/<frame-id>.md` 必须能单独交给实施者。顺序固定如下：

1. **本图身份**：frame_id、page_id、精确路径、SHA-256、批次、状态、尺寸或已知显示条件；展示原图或提供可直接打开的原图链接。
2. **本图整体目标**：说明主体、信息层级与期望效果，并写出应保留的内容。
3. **逐项修改**：按 frame_plan.action_ids 的实施顺序展开。每项写 opinion_id/action_id、具体位置、当前表现、目标效果、本图改法、保留项、依赖与复核，并在该动作下直接链接 action.item_ids 对应的单项报告。不能只写“按 F06 调整”，也不能让实施者去页尾全量列表中猜哪些项支持当前动作。
4. **本图待验证**：列出证据不足的相关点或状态及补验动作，与已确认修改区分。
5. **本图复核清单**：先复看整屏，再检查涉及对象、方法及关联状态；说明需要同时回看的其他截图。
6. **依据入口**：链接总报告、统一意见和本图完整检测记录。完整记录在 results/INDEX.md 按 frame_id 分组，保留每项 JSON、Markdown、结论与覆盖入口；单图页不再铺列全部检测项。跨图项可在参与图索引中重复出现，但只计为一个检测项。无需修改的图也保留完整记录入口。

同根因在不同图上的具体落地应分别描述。例如普通功能面板的统一意见是“容器与内容量协调”，设置图可以收紧标题和调节区的距离，背包图可以围绕三行道具调整承托高度，榜单图则需保留排序、周期和长列表空间。只有该图证据支持时才采用相应改法，不凭例子强加方案。

文字审美调整必须定位到具体品牌名、阶段标题或固定主行动，写明现有字形表现、目标和本图改法；角色或配色协调不能作为品牌标题无修改项的充分理由。保留数值、规则、说明的职责与排版，不把展示字方案扩大到所有正文。

## 无需修改、缺证与特殊材料

- **无需修改**：仍生成单图报告，写“本次未发现已确认修改项”、应保留内容及检测范围；不为了凑清单制造问题，也不把 keep 写为全量验收通过。
- **缺少材料**：本图报告说明哪些判断仍 pending、需要补什么。材料损坏或消失时回到队列处理，不能保留失效图片的最终修改清单。
- **同页不同状态**：分别输出，某状态成立的修改不能无依据扩大到其他状态。例如少量内容的密度意见不自动作用于满载状态。
- **参考稿或过程拼图**：明确 reference_only，并定位其中具体子页面；一张拼图包含多页时在单图报告内按子页面分小节，逐个写其可支持的修订或保留。运行事实不从拼图推断。
- **raw/logical 对**：分别给入口，注明同一来源；原始桌面图只定位其中游戏区域，具体 UI 改法按对应画面写出，不把桌面外框当产品布局。
- **跨截图关系意见**：为每张实际受影响图生成 action；仅作对照、无需修改的图写明其保留与复核作用，不能被遗漏。

## parent 收口检查

1. 当前队列 frames 中每张截图恰有一条 frame_plan、一份 `pages/<frame-id>.md` 和索引行；目录外或已取消材料不混入最终清单。
2. 统一意见及 action.item_ids 都指向有效采纳快照；动作的依据属于所属意见并实际支持本图修改，每个 action_id 在对应单图报告中出现，附直接单项报告链接，方向与统一意见一致。
3. 同图的多项动作无冲突，依赖无缺失或成环；DECISIONS.json、单图报告和逐图索引的动作顺序一致，前置动作先于后续动作，页外依赖有明确入口。局部改法保留整体主题和必要操作空间，不能互相挤压。
4. 单项 JSON 与 Markdown、DECISIONS.json 与 REPORT.md、逐截图报告之间无结论漂移。回看实际截图验证定位，不以“所有文件存在”代替内容检查。
5. 总报告按“整体结论 → 统一意见 → 逐截图修改导航 → 检测点/方法覆盖 → 整体复核计划 → 剩余缺口”交付；最终回复同时链接 REPORT.md 和 pages/INDEX.md。

在修改后的画面尚未形成时，交付的是修改方案和复核要求；不提前标记已改善。此处只定义审核交付，不授权实施代码、素材、提交或发布。
