# 玩家、可访问性与性能方法

执行范围由检测点节与 QUEUE.json 的当前条目确定。只执行该点选中的方法，逐方法记录实际步骤、证据与限制，写回同一条目的结果；不自行新增或扩大检测点。

[M-20](#m-20) · [M-21](#m-21) · [M-22](#m-22)

## M-20

**方法**：玩家理解观察

- **适用输入**：目标玩家或明确说明局限的代表者、真实任务和待理解内容。
- **步骤**：给出任务而不先解释预期答案；观察其寻找、解释和操作，记录原始误解与困难；再询问因果或用途理解，区分提示前后表现。
- **产出**：参与条件、任务、实际解释与行为、困难位置和样本边界。
- **限制**：审核者自己会操作、按提示点对或文案存在不证明玩家已理解；没有参与材料时相关结论待验证。
- **本点执行与产出**：用本点对应的真实任务观察目标玩家或代表者，记录提示前后的理解与困难。

## M-21

**方法**：可访问情境检查

- **适用输入**：已约定的目标玩家条件、观看和输入环境及实际支持的辅助方式。
- **步骤**：选取与任务相关的静音、低亮度、单手、阅读或精细操作受限条件；按实际能力完成关键任务；记录障碍和可用替代，不把界面便利与玩法挑战混为一谈。
- **产出**：选择条件的依据、执行表现、信息或操作障碍及缺口。
- **限制**：模拟条件不是所有相关玩家的真实体验；需要理解证据时配合 M-20，不强加未经约定的能力。
- **本点执行与产出**：在已约定且与本点相关的观看或输入受限条件下完成任务，记录障碍与替代。

## M-22

**方法**：繁忙过程与性能观察

- **适用输入**：目标运行环境、代表性复杂局面或并发效果，以及现有性能和响应目标。
- **步骤**：说明设备、构建、负载与测量方式；执行必要操作，观察并在可测时记录响应、更新和卡顿；定位装饰与必要反馈的竞争，对照有效目标判断。
- **产出**：环境、操作、测量值或明确的观察证据、受影响的必要反馈。
- **限制**：桌面录屏或类型检查不能替代目标设备性能；无标准时说明现象，不编造帧率或耗时门槛。
- **本点执行与产出**：在本点代表负载下记录目标环境的响应、更新和必要反馈，不用静态图推断性能。
