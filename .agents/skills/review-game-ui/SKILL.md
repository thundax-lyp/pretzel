# Review Game UI

按“原则 → 检测点列表 → 检测队列 → 本点方法组 → 单项报告 → 统一意见 → 逐截图修改单”执行。parent 先看整体、拆对象并建队列；subagent 按检测点执行，parent 回收后统一方向，再为每张截图落实改法并复核整体。

## 主动调用与目标参数

仅在用户主动调用本技能时执行。参数为待审核目标的文件名或路径；不因普通开发任务涉及游戏 UI 就自动启动审核。

```text
$review-game-ui home.png
$review-game-ui frontend/miniprograms/eyes-and-legs
$review-game-ui "/absolute/path/home ready.png"
```

- 绝对路径直接定位；相对路径从当前工作目录解析。仅给文件名时，先检查当前目录，再在当前工作区查找同名文件；唯一匹配才可使用，多处同名时列出候选并让用户明确目标。
- 文件参数以该文件为审核目标；目录参数先枚举其中与 UI 审核相关的材料，再按页面与对象建立范围。不自动改为审核整个项目，关联文件只在解释目标所必需时读取。
- 参数缺失、目标不存在或无法唯一定位时，说明具体缺口并请求补充文件名或路径，不自行选择最近截图或默认页面。
- 源码、设计文档或静态材料只支持相应范围的判断；需要实际画面、输入或运行事实的检测点仍按证据缺口记录。

## 按角色直接读取

parent 开始审核时：

1. 直接读取 [设计原则](../../../docs/30-designs/GAME-UI-UE-PRINCIPLES.md) 与 [审核流程](references/review-workflow.md)，确认类型、目标体验、整屏观察和证据边界。涉及具体产品数值或行为时，再读相关当前需求、契约和方案。
2. 从 [检测点列表](references/review-checks.md) 选点，直接定位 `checks/<category>.md#<point-anchor>` 的对应节；每点保留自己的判据、最低证据和方法组。分类文件共享对象范围，执行与返回规则由公共协议维护。
3. 读取 [检测队列](references/review-queue.md) 建立 QUEUE.json；分派时读取 [并行协议](references/parallel-review.md) 和 [统一单项返回](references/result-contract.md)。
4. 采纳结果后读取 [报告交付](references/report-output.md)，形成统一意见和逐截图修改单。

subagent 接到分片后，按 point_ref 的文件路径与锚点读取指定检测点节，再读取其选中方法对应的 `methods/<topic>.md#<method-anchor>`、统一返回契约及必要材料。同一文件可容纳多个点，但不因此扩大任务；每个点的全部选中方法仍由同一 owner 收口。共享步骤与产出要求按[方法索引](references/review-methods.md)定位，无需通读其他节。

先区分参考稿、旧图和当前材料，保留版本、尺度、动态和事实缺口。逐项提问由审核者作答，已有上下文足够时直接执行。

## 执行顺序

1. **整体观察与拆分**：parent 先看完整画面和必要相邻流程，记录任务、情绪、重心、比例、风格、保留项及失衡，再按区域、复合对象、子元素和关系拆分。文字按品牌名、情绪/阶段标题、固定主要行动、数值/规则/正文分别识别；品牌标题不能并入普通文字组而失去独立判断。
2. **检测点入队**：为每张截图的对象与状态选择全部适用点，读取该点自己的方法组，写入队列并记录条件性方法选择依据。默认一项一个检测点，多图关系显式列出参与截图。
3. **并行检测**：将独立队列项批量分给 subagent；每项由唯一 owner 完成整组方法，分别返回 `results/<item-id>.json` 和同名单项报告。共享运行输入统一协调，小范围或工具不支持并行时按相同契约串行。
4. **回收与统一意见**：parent 每收到一项或一个分片的结果，先确认条目身份、revision 和返回文件齐全，及时持久化 returned，再核对截图哈希、完整方法组、证据、结论和覆盖状态，分别写入 accepted 或 needs_recheck；不等所有分片结束才批量接收。处理分歧后按共同根因合并。结构化返回只用统一 JSON，不接受各自定义的 CSV/TSV 字段。
5. **逐截图展开**：先形成 DECISIONS.json 中的统一 opinion，再为每张截图写独立 action 与 `pages/<frame-id>.md`，包含本图位置、当前表现、目标、具体改法、保留、依赖和复核。动作按实施依赖排序，每项直接链接支持该动作的单项报告，完整检测记录通过本图索引访问。无需修改或仍缺证的图也有独立清单。
6. **整体复核**：parent 回看完整画面、跨对象与跨页关系，检查各页动作有无冲突；新效果未形成时交付复核计划，不能提前宣称已改善。

必要方法及证据完整、符合本点判据才可通过；已确认偏离但仍缺方法证据时，可为需调整且覆盖未完成。不能用一个方法通过代表整点，也不因发现问题跳过其余方法。

固定大字承担品牌或情绪职责时，优先评估定制美术字，执行文字分类中的 TXT-11.1/11.2 与 M-26；固定主行动按其职责评估个性字形。主动判断文字自身的造型、美术完成度与主题记忆，不能以可读、配色协调或角色已有个性代替。静帧已支持的审美调整直接给出对象级改法，真机阅读、动态和命中缺口单独保留。

## 输出与完成边界

用户指定输出位置时遵循其位置；未指定时使用仓库根目录 `logs/game-ui-review/<review-id>/`。单项结果、统一意见及报告文件按 report-output.md 的固定结构写入。parent 独占队列、统一意见、总报告和逐图清单，worker 只写所领项的结果。

最终同时链接 **REPORT.md 与 pages/INDEX.md**。总报告说明整体方向、统一意见、覆盖和缺口；每张截图的修改单能够独立交给实施者，不只写“按全局意见修改”。raw/logical 和同页不同状态分别有入口，参考/过程拼图按子页面定位，不混成同一运行版本。

只判断有证据的版本和状态，未完成项明确保留。默认交付审核结果与修改建议，实施代码、素材或外部写操作按用户当前授权范围执行。
