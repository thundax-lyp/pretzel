文档阅读顺序

1. **《PRD-游戏前端产品需求文档》** — 一切起点。先搞清楚产品形态：层叠卡牌消除 + 动物图鉴收集 + 好友排行榜，页面结构、各弹窗规则都在这。不知道“要做什么”，后面全是白读。 \minigame\PRD\1. PRD-游戏前端产品需求文档.md"

查看UEUI设计稿和其他文件

注意：:\minigame\UEUI\3-没办法纠正AI.png 这张效果图片生成有点问题，题目提示区位置错了


2. **《玩法说明文档-关卡与难度设计》** — PRD 的玩法深化篇。卡牌怎么叠、关卡和难度曲线怎么设计，前端实现玩法逻辑的核心依据。

3. **《小游戏后台技术方案》** — 架构总览。主域/子域（开放数据域）分工、云托管 + MySQL 技术底座、“好友榜走微信关系链、服务端不管榜单”的边界划分，先建立全局认知再钻细节。

4. **《数据库与Admin门户设计》** — 数据模型权威来源。所有表、字段、索引以它为准，写任何涉及持久化的代码前必须对齐。

5. **《接口说明文档》** — 接口契约权威来源。通用约定（鉴权、信封、错误码）+ 小游戏端 5 个接口 + 管理端 20 个接口的字段定义，前后端联调就靠它。（新增了好友历史榜需要新增接口）

6. **《开发详细设计文档》** — 收口文档。调用关系、执行顺序、事务边界、异常分支、时序图。它明确说了“冲突时以《接口说明文档》为准”，所以必须放在 3/4/5 之后读，否则看不懂引用关系。

7. **《加固方案》** — 预留安全能力（签名接口），当前 MVP 未启用，了解即可，做到对应阶段再细读。（一期不开发）
