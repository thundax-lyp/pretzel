# 第二关离线模拟验收

## 范围与结论

验证对象是 `scripts/game-design.py` 的离线关卡生成、筛选、实验道具和规则回放，不是已接入微信或 Java 后端的游戏。第二关保持 12 题、48 张牌、7 格卡槽，当前题与下一题可见，有效游戏时长目标为 4—6 分钟。

零储备的当前题与下一题规划策略下，视频道具使用比例为 81.9%，全部在最多三次视频奖励内通关；满储备时视频使用比例仅为 6.6%。因此这里只验证了零储备场景接近目标，不能认定全部玩家有约 80% 会观看广告。真人观看意愿、储备分布、心算速度和误操作均未验证。

## 固定配置与样本

- 布局为 `three-peaks`，三个独立山峰，每峰由底向上 5、5、4、2 张，共四层；初始六张牌可点击。
- 题量曲线为 `balanced`，参考用牌数量为 3、3、3、4、4、4、4、4、4、5、5、5；其他张数的合法整槽组合仍允许消除。
- `challenging` 筛选只使用三个校准决策重复 -3、-2、-1，要求三次均未通关、至少完成前三题、没有搜索触界。
- 调参请求种子为 2026110400—2026110439，40 个棋盘、每棋盘五次决策，共 200 次。
- 冻结配置后，验证请求种子为 2026120000—2026120199，共 200 个新棋盘。每个棋盘五次决策重复 0—4，每组 1000 次。
- 验证集从 555 个候选中筛出 200 个棋盘。所有候选筛选记录均保留；最终决策重复不参与筛选，没有按真实广告行为改变题目或牌面。
- 零储备、满储备、无道具和只规划当前题四组使用完全相同的验证棋盘；首次道具前的主实验轨迹与无道具对照逐一相同。

每个棋盘均保留并重放完整的无道具参考解；允许玩家的其他合法组合导致后续无解。筛选只标定指定策略的难度，不证明对真人或任意策略有同一失败率。

## 实验道具

- 移出：从卡槽中选择 1—3 张牌进入无限暂存区，逐张放回；移出后重新判断整槽匹配。实验中可先取阻挡牌再移出，并提示当前题的一组解法。
- 可验证重排：在现有棋盘占用位置间重新布置剩余牌，保持属性、数量、卡槽和暂存区；先证明所有剩余题目能按规则完成，再发放并提示当前题。
- 纠错回溯：恢复到最近找到可验证修复方案的历史起点，修正并布置牌面，自动重放到原来的当前题，玩家不用手动重做已完成题目。保留当前题进度，提示当前题的一组解法，不返还视频计数、使用次数或局外储备。

全部仅限仍在进行的第二关；满槽失败后不能使用，不提供复活。每次成功视频奖励获得一种道具的一次额度，三种合计最多十次，优先使用已有同种储备。无效操作不消耗使用额度；已成功发奖的视频计数不因回溯返还。没有可验证方案时不进入该道具的领奖流程。

数值分配仅证明属性可分配；工具还会实际生成布局、验证完整路线，并导出独立回放可核验的修复证书。证书及参考解是内部设计材料，不能直接发送给客户端。

## 时间模型

时间不包含广告播放和切后台，仅按显式假设计账：人工取牌每次 2.5 秒，每题额外思考 10 秒，道具交互每次 8 秒，自动修复重放每题 1.5 秒。该参数没有真人计时依据，不能作为时长验收通过的证据。

主实验模型中位数为 252 秒，即 4 分 12 秒，P90 为 264 秒；全部样本落在 4—6 分钟。但敏感性分析显示结论高度依赖思考和点击假设：

| 假设，依次为人工取牌、每题思考、道具交互、自动重放秒数 | 中位数 |    P90 |
| ------------------------------------------------------ | -----: | -----: |
| 快速：2、7、5、1                                       | 188 秒 | 196 秒 |
| 默认：2.5、10、8、1.5                                  | 252 秒 | 264 秒 |
| 慢速：4、15、12、2                                     | 390 秒 | 408 秒 |

应通过真实试玩分别采集有效操作时间、思考停留、广告时间和后台停留，再校准模型。当前不能声称已验证真人时长为 4—6 分钟。

## 验证证据与复现

工具与规则测试包含生成确定性、覆盖、整槽匹配、满槽优先级、暂存超过十二张、储备、视频共享上限、无效操作不扣库存、回溯不返还消耗、自动修复范围、修复证书防篡改、时间模型不改变玩法及输出不覆盖，共 24 项。

完整运行含调参 200 次和验证四组各 1000 次，共 4200 次；每次都使用独立的集合与坐标回放核验，重排与回溯还重放完整剩余解证书。独立实现共享动物属性表，不代表与现有 Java 领域实现完成了交叉验证。

原始配置、候选筛选、棋盘、操作和统计保存在 `logs/game-design/` 下的 tuning、validation、validation-reserve、validation-no-tools、validation-current 目录，均被 Git 忽略。每组输出 `runs.json` 与 `summary.json`；代码 SHA-256 为 `a0414112377af588b5ba9466bc94f4bba2aac57c1f40d912663c7ef191b3c78c`。

```sh
python3 scripts/game-design-test.py
python3 scripts/game-design.py simulate --boards 200 --repeats 5 --seed 2026120000 --difficulty challenging --output logs/game-design/new-validation
python3 scripts/game-design.py verify --output logs/game-design/new-validation
```

输出路径须尚不存在。切换 `--reserve 1`、`--policy current`、`--mode none` 分别复现对应对照，输出到其他新目录。

## 结论边界

- 目前接近的是零储备模拟的广告需求，不能混称为全体玩家的观看率。满储备免费额度足以覆盖绝大多数本轮困难；保留既定储备规则时，需要先获得真实库存分布，再判断整体目标。
- 策略知道全部卡牌属性与覆盖关系，按提示操作，接受推荐道具，且视频成功率与接受率均为 100%；没有模拟只看露出牌、心算错误、点击错误、拒绝广告或中途离开。
- 修复道具使用完整未来数据规划，但只给玩家当前题提示；自由策略只使用当前及下一题。模拟器的理性预判使其能在失败前使用道具，真人可能来不及纠错。
- 主实验有 76 次搜索触界记录，只规划当前题组有 87 次。触界不是数学无解；修复方案即使搜索未穷尽，也必须有完整证书才实际发奖。无法证明的方案不收费。候选组合枚举上限还限制了策略择优能力。
- 正式 Java 领域、微信渲染、实际道具接口、广告回调、真人时长及商业收益均未接入或验证。模拟 100% 通关不能解释为真人 100% 通关。
