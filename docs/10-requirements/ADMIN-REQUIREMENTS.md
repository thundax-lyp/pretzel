# 管理端需求

## 已实现范围

管理端用于维护系统用户、角色、菜单权限、部门、字典与系统日志。支持验证码与 SM2 密码传输的登录、令牌刷新、退出、服务端菜单和权限加载。管理用户与微信玩家身份独立。

界面采用 React、TypeScript、Ant Design 和 Pro Components。页面根据权限控制入口与操作状态，后端独立执行认证、功能权限和数据归属校验。

用户管理支持列表筛选、分页、编辑、头像上传、状态切换和批量操作；不能通过界面操作管理自身或同级及更高等级的用户。角色管理维护状态和菜单授权，授权与撤权需要立即影响后端访问。部门、菜单支持树形组织、排序与层级操作。

首次管理员必须显式开启初始化并提供符合规则的密码。系统不提供共享默认密码，不覆盖已有同名用户的凭据。

## 游戏运营目标

后续管理能力需要承接动物内容、题目与布局参数、道具与广告获取、收集记录、当周榜单与历史归档查询。此部分属于待实现范围，页面与接口必须跟随明确的产品规则设计，不能将当前系统管理 CRUD 视为游戏运营后台已完成。

## 验收重点

登录失败不残留登录态或权限；权限加载失败不能进入已认证可用状态；危险操作需确认；失败保留可重试信息和未提交表单；排序不能丢失隐藏行；列表区分首次失败与保留旧数据的刷新失败。
