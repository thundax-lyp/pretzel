# 管理认证与权限契约

## 当前 HTTP 协议

管理接口前缀为 /pretzel-admin-api/api。请求携带 Access-Token，不能使用前端按钮是否显示作为后端授权依据。

成功业务码为 COMMON-00000。未认证与禁止访问等业务失败可能采用 HTTP 200 返回，调用方必须同时检查业务码。COMMON-00002 表示未认证，COMMON-00003 表示无权访问。

登录前调用 /auth/session/pre-auth-session/request 取得登录上下文及密码加密公钥；客户端按现有服务契约进行验证码与 SM2 密码传输，密文包含完整非压缩点前缀 04，不发送明文密码。

预认证请求按 RequestIpUtils 识别的来源地址分别限流，默认每个来源 60 秒内最多 10 次，通过 pretzel.auth.pre-auth-request-limit 和 pre-auth-request-window-seconds 配置；Redis 原子计数，窗口到期后恢复，不按全站未完成登录会话数限制。部署代理应覆盖客户端传入的来源头。验证码必须提交非空值，并与服务端未过期的非空值匹配；绑定手机号等上下文时，绑定值同样不能为空且必须一致。显式启用的验证码白名单按配置生效。

取得令牌后必须成功加载当前用户权限才能完成登录会话建立。权限加载失败清除令牌和权限。/sys/current-user/permission/list 提供权限集合，/sys/current-user/menu/list 提供可见菜单。

令牌清理同时清理权限；账号切换同时取消并清理受保护查询，延迟响应不得覆盖新账号或以新账号重试旧操作。共享登录态的标签页串行消费刷新凭据，等待者复用已轮换的令牌；会话采用固定有效期，普通请求不执行续活写回；刷新沿用同一次登录会话，退出撤销该会话全部访问与刷新凭据；密码变更撤销用户既有会话。退出失败时提示失败并保留凭据供重试。刷新、退出、用户禁用和角色撤权需保持服务端会话与客户端状态一致。

权限快照写入与刷新按会话串行化，旧快照不得缩短已刷新的有效期。权限事实从数据库读取，快照使用包含进程生命周期标识的版本；权限变更在事务提交后失效。个人资料更新只写姓名、邮箱和手机号，不回写登录上下文中的权限、等级或状态。

## 代码归属

admin-web/src/api/http.ts 统一解释业务响应和处理网络；src/auth 保存认证协议与令牌、权限存储；src/session 编排登录后权限加载及当前用户信息；业务页面不直接调用 fetch。
