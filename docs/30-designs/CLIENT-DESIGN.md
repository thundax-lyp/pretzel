# 客户端与管理端组织设计

## 微信小游戏

客户端采用 Cocos Creator 3.8.8（3.8 LTS）、TypeScript 和 2D UI，项目路径沿用 frontend/miniprogram。创建工程时将 package.json 的 creator.version 固定为 3.8.8，编辑器和构建环境使用同一版本。启动、首页、游戏由 Start 场景中的 GameClient 在同一 Canvas 上切换，弹层与牌区使用原生 Cocos 节点。棋盘触摸命中与覆盖规则分离，Tween 和音频组件负责表现，业务状态不依赖场景节点。

登录、HTTP、广告、分享、生命周期与本地存储经微信小游戏平台适配层接入。游戏规则与接口 DTO 保持纯 TypeScript。Cocos 编辑器构建微信小游戏目标后，将构建输出导入微信开发者工具，验证真机登录、网络、广告、输入和安全区。编辑器维护资源 .meta 与 UUID。

客户端按游戏接口契约使用玩家会话与版本化快照。编辑器预览提供独立的本地样本，正式构建通过 HTTPS 接入服务端。

游戏页分离状态、操作与动画：覆盖关系决定可点击性；卡槽和暂存区保存牌实例；动画不直接发放奖励或确认服务端结算。多行可滚动暂存区按 restoreAnchor 判断可复位性，底牌归位后免费回到棋盘原位置；灰显受阻牌并显示原因，复位重新形成遮挡。

后台提供第二关生成数据，客户端根据明确坐标和层级渲染。屏幕缩放不能改变覆盖语义或导致不可点击牌被选中。

### 页面状态与反馈

- 启动页根据初始化进度驱动乌龟动效，成功后自动进入首页，失败时显示重试。发布信息与适龄提示放在底部固定区域。
- 首页分别读取本周广场动物、永久图鉴及榜单。领奖弹层一次展示一只，广场按本周实际领取记录刷新。图鉴按编号排列，以解锁周期计算 NEW 标记。榜单提供本周和历史逐周查询以及加载、空榜、失败重试状态，参与范围待确认。
- 首页与游戏页共用设置交互。音乐和音效分别持久化；切后台暂停播放。模态弹层只有一个活动状态，阻止棋盘输入并暂停有效计时。游戏内放弃需二次确认，取消恢复原对局。
- 游戏页按题目、棋盘、暂存区、卡槽、道具排列。第二关区分当前题和下一题。可取状态来自覆盖判定，动效消费已确认的操作结果。暂存区限制可视高度并允许内部滚动。动画及操作确认期间锁定相关输入，点击不排队。
- 第一关禁用道具入口，第二关展示库存及零库存时的获取入口。领取等待期间锁定对应入口。结算区分待确认、胜利和失败，恢复时按已确认结果渲染，不重放已结束音效。普通分享与分享领奖走不同交互路径，领奖入口受可验证证据约束。

## 管理端

frontend/admin/src/pages 按业务域组织页面和服务。api 只提供传输能力，auth 保存底层认证与令牌，session 组织当前用户及会话建立。跨页面当前用户服务不混入用户管理页面的 CRUD 服务。

生产源码放在 frontend/admin/src，测试放在独立的 frontend/admin/test，目录对应被测源码；测试初始化统一放在 test/setup.ts。测试通过 @/ 引用生产源码，生产源码不依赖测试目录。两者分别进行 TypeScript 检查，Vitest、格式与 lint 检查覆盖测试目录。

布局直接使用 ProLayout，页面骨架使用 PageContainer，列表使用 ProTable，筛选使用 QueryFilter，表单使用 ProForm 或 DrawerForm，基础控件直接使用 Ant Design。角色菜单树、用户头像等业务组件可以封装自己的状态与协议，不包装官方组件的同义 props。

## 状态与验证

管理端远程状态使用 TanStack Query。小游戏通过 GameApi 与 RunState 消费版本化快照，保留未知操作 ID 并原样重试，状态校验与表现分离。界面负责交互状态与可理解的错误反馈。权限、列表排序、草稿保留、重复提交、关闭重开与窄屏布局必须保持一致。

ArchUnit 在 Java 测试阶段检查依赖与包归属。前端使用 Oxlint 和目录结构检查，Prettier 与 Spotless 约束 4 空格缩进，CI 显式执行对应验证命令。
