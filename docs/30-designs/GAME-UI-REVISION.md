# 游戏 UI 修改意见与文字资源方案

本方案基于已移除的《腿了个腿》客户端原型。

本方案按 GAME-UI-UE-PRINCIPLES.md 的类型取舍、整体审美与分类原则复核当前界面，审核由 review-game-ui 技能执行。其 references/review-checks.md 是检测点列表，各 `checks/<category>.md#<point-anchor>` 节独立维护检测点的判据和方法组，共享方法按操作主题维护，review-queue.md 据此建立检测队列；result-contract.md 统一单项返回，report-output.md 规定统一意见和逐截图修改清单。检查覆盖当前 Cocos 工作区、01—11 页面截图、已有启动页与首页新截图，以及 screens 下的 18 张参考效果稿。启动页和首页已有部分实现，以下区分保留项、待修改项和待验证项，不把旧截图中的问题当作当前实现现状。

本方案定义待实施的界面调整，参考效果稿仍需按下文修正。微信工具本地预览不能证明正式在线、广告、分享、奖励与隐私服务接通，真机触摸和性能仍需单独验收。

## 整体效果与修改方向

游戏中的观察、求和与取牌需要稳定局面；首页的动物收集需要亲和、轻松且有场景感；过关演出可以更活跃。整体方向采用草地动物园、立体动物与少量木质边饰，让动物、棋盘和成果成为各自页面的主角。动效围绕操作和阶段达成展开，不以持续热闹为目标。

保留启动页品牌资源接入与乌龟进度，品牌字形仍需按自身个性和美术完成度定稿；首页已有的信息分级、分页和深绿主操作继续保留。首页的可读性改善已具备画面证据，整体审美仍需处理场景与信息容器之间的关系；不能因局部文字清楚就判定整屏设计完成。

| 画面     | 整体观察与判断                                                                                                             | 修改方向                                                                                                   |
| -------- | -------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| 启动页   | 品牌与动物能说明主题，进度建立了准备过程；主视觉、加载与调试操作仍较分散，亮面木按钮比辅助身份更醒目                       | 以品牌和动物形成紧凑主视觉，进度承接视线；控制调试入口重量，保留轻松气氛                                   |
| 首页     | 动物与文字已分开，主次操作更明确；大面积规则浅色容器包住少量动物，周围仍是鲜明草地图，容易呈现“信息托盘放在风景上”的割裂感 | 保留内容布局与清楚标签，把中心承托组织成同一片草地；用地形、站位、尺度与柔和阴影建立场景感，平衡主体与留白 |
| 游戏页   | 明亮草地、顶部木牌和底部道具均有较强存在感，两堆密集牌面在中间显得狭窄；整体注意力分配没有充分突出观察与求和               | 先调整棋盘与辅助区域的体量，再处理属性排版；降低玩法区域周围的装饰竞争，保留统一动物风格                   |
| 功能弹层 | 大熊猫、厚标题与大面板承担主要视觉重量，设置、背包和榜单的真实内容相对稀少；不同功能看起来像同一种庆祝面板                 | 根据任务配置标题、装饰和内容密度，功能区重在内容组织；保留小型主题细节，结果演出再突出角色                 |
| 页面之间 | 首页与动物详情已趋向平静、简洁，其他弹层仍沿用强木框和大熊猫，界面语言衔接不足                                             | 统一轮廓、字体层级、色彩关系和材质用量；允许场景、功能与结果有不同强度，使其仍属于同一游戏                 |

这些是画面关系上的审美判断，不等同于已经量化的行为缺陷。先确定构图、主体比例和风格关系，再让字号、控件和状态修改服务这个目标；新的整屏效果尚待制作和复核。

## 审核对象与分类结论

按玩家任务拆为区域及复合对象，再对对象应用相应规则。表中的类别可交叉，不按脚本文件或图片数量计算覆盖。

逐项复核采用提问式思考，按审核规则回答判断、理由与处理方向。例如查看动物名称时，先问字体气质、字号和颜色是否与动物场景协调，再问长名称与数量变化后是否仍然清楚；查看主按钮时，先问视觉重量是否符合首页重心，再检查操作与状态。问题用于验证方案，不把尚未形成的新版效果写成已经通过。

覆盖范围同时检查整体、区域、对象、状态和对象间关系。分类检测细则按现有能力选用，不据此增加广告、付费、复杂输入或其他未约定功能；缺少动态与设备证据的已有能力仍列为待验证。下文修改项不代表全部适用细则已经取得运行验收证据。

| 页面或任务     | 区域与主要对象                                                       | 对象类别                             | 逐项关注的关系                                     |
| -------------- | -------------------------------------------------------------------- | ------------------------------------ | -------------------------------------------------- |
| 启动准备       | 品牌与动物主视觉、进度与状态、重试或调试入口、底部提示               | 背景、游戏对象、文字、控件、反馈     | 主题辨识、观看顺序、主次重量、加载状态             |
| 首页收集       | 页头、本周摘要、动物与地形、名称数量标签、分页、领奖条、挑战与次导航 | 背景、承托、收集对象、文字图标、控件 | 场景完整感、动物尺度与聚散、信息层级、入口稳定性   |
| 游戏对局       | 当前题与下一题、棋盘牌堆、暂存、七格卡槽、道具与消息                 | 游戏对象、承托、文字、控件、反馈     | 棋盘占比、遮挡层次、双属性对应、操作与动效冲突     |
| 设置与内容浏览 | 功能面板、业务行或列表、正文、详情、周期切换与返回                   | 承托、文字图标、控件、弹层内容       | 装饰与内容比例、扫读、滚动、返回路径与底层关系     |
| 阶段结果与领奖 | 熊猫与庆祝、结果与原因、奖励对象、选择区、下一步操作                 | 游戏对象、弹层内容、文字、控件、反馈 | 演出和信息分区、结果真实性、主次操作、重复进入状态 |

复合对象先看完整效果，再拆必要子元素。例如动物标签需同时检查动物、阴影、名称、数量及站位关系；道具按钮需同时检查底板、图标、名称、数量与状态，避免各部分单独合格却组合拥挤。

## 整体目标

保留草地动物园、少量木质边饰和立体动物风格。首页突出收集成果，游戏突出数字与可操作牌，弹层突出内容与下一步行动。通用设计原则指导取舍，以下参数是本项目的设计取值，按实际设备和试玩结果调整。

### 项目视觉参数

| 项目     | 设计基线                                                                                                               |
| -------- | ---------------------------------------------------------------------------------------------------------------------- |
| 字号     | 页面或弹层标题 24、主按钮 20、正文 16、辅助文字 14，均为逻辑像素；核心目标数字以不小于 24 起评，牌面按页面方案单独验证 |
| 点击区域 | 普通控件至少 44×44 逻辑像素，主按钮高 56，相邻独立控件间距以 8 起评；卡牌命中仍服从实际覆盖关系                        |
| 对比度   | 功能文字及其图片字与背景至少 4.5:1，识别控件与状态所需的非文字线索与邻接背景至少 3:1；品牌单独评估，禁用原因仍需可读   |
| 普通动效 | 按下后 100 ms 内开始反馈；入槽约 150—250 ms、消除约 200—350 ms、弹层过渡约 150—220 ms，不包含网络等待                  |
| 结果演出 | 强调段约 600—1000 ms，之后保持静态可读结果；实际范围与输入锁按事件确定                                                 |

尺寸与字号统一按后文坐标约定换算。首页双行按钮的进度小字保留其局部设计，不将这一例外推广为通用字号。

### 视觉与布局

- 首页保留外围草地、树木和花草，动物主场景使用低细节浅色草地，文字落在稳定的实色底上；游戏棋盘后方降低背景饱和度和细节对比。
- 主操作使用深绿色实心按钮配白字，文字区域不放亮绿高光；次操作使用奶油色或透明按钮，禁用态同时说明原因。首页具体颜色、尺寸和对比验证见首页方案，不能把启动页白描边批量套用于所有文本。
- 标题、正文、辅助信息分级，不再全部使用同等粗体强度。
- 游戏按顶部题目、弹性棋盘、暂存区、七格卡槽、道具栏布局。统一换算设备安全区与设计坐标，同时避让微信胶囊、刘海和底部手势区。
- 弹层区分紧凑提示、设置/背包功能面板、图鉴/榜单/正文滚动面板；高度按内容和可用空间决定。
- 大熊猫用于过关和结算演出；日常功能面板采用小型标题装饰。木框、标题、动物装饰分别制作，避免整图随容器拉伸。
- 当前目标、牌面与卡槽始终按眼睛、腿数顺序展示，文字与图标并用。卡槽可显示眼睛 2/5、腿数 4/7；超过目标只提示，仍遵循现有判定，不提前失败。

### 事实与状态

- 加载、可用、禁用、请求处理中、失败重试、结果待确认需要独立表达。
- UI 不提前增加库存、不承诺未接通的视频/分享奖励，不把请求失败当空榜。
- 解锁种类、累计领取次数、本周实际领取数量分别呈现。
- 保持当前三页面结构、两关规则、整槽匹配、七格容量、服务端事实和无复活边界。

### 通用渲染与操作调整

1. **背景与资源。** clear() 不再让同一幅风景承担所有内容底板。游戏顶部、卡槽统计和消息区使用实色承托，棋盘背后使用浅色低细节区域。ui-skin.ts 目前将资源作为 SIMPLE Sprite 铺满目标矩形；背景改为等比裁切，面板和按钮底分片或九宫格，动物与图片字保持比例。换皮后仍检查最终合成，不能只验证底色。
2. **文字角色。** 调整 label() 的字号、字重、对齐与溢出参数：正文左对齐和自然换行，辅助字保留可读对比，关键数字不使用 SHRINK。首页现有 Label 分级继续保留；启动页 startText() 的通用白描边删除，仅品牌资源允许独立描边。牌面目标和已选值按眼睛、腿数固定顺序对齐。
3. **触摸区。** 以下均为 375 逻辑宽、750 设计宽，即 s=2 时的代码换算，不是真机测量：设置 102×62 设计单位约为 51×31 逻辑像素；音量加减 76×66 约为 38×33；榜单切换 130×59 约为 65×29.5；通用关闭 490×73 约为 245×36.5。补到至少 44×44 逻辑像素并重新安排间距，不能扩大到邻近控件上。按钮父节点保持命中尺寸，按压只改变展示层；滑出取消、滚动取消、模态阻断须实测。
4. **弹层。** 保留一次一层与遮罩不关闭规则。紧凑通知不带大熊猫；设置、背包按业务行组织；图鉴、榜单、长正文中部滚动，操作固定在内容之外。面板最大可用高度按安全区计算，正文高度按实际排版计算，删除 body.length>60 的高度决策。背景、标题、内容共同淡入或移动，命中层不缩放，避免现在只 pop(body) 而文字仍挂在 shade 上。
5. **等待与错误。** work()、图鉴读取、榜单切换和结果重试在原入口或面板内显示处理状态；禁止仅靠 busy 吞掉点击。失败后恢复实际可用入口；结果未知时说明正在确认原操作，不诱导重新操作。确认类按钮使用“确认移出”“确认放弃”“重试原结算”等具体动作。
6. **特效与输入。** 将 submit() 的必要飞牌、消除、复位及布局移动纳入 animating 状态，完成或取消后解除相关锁；切页面和恢复快照后忽略旧动画回调，点击不排队。庆祝限制在标题外缘或独立演出区，道具生效提示移到固定消息条，不盖棋盘。普通功能面板不使用庆祝弹跳，失败使用短提示与静态原因；切后台暂停，恢复不补播已经结束的奖励或事件音效。

## 固定文案是否使用图片字

### 结论

保留启动页已经接入的资源加载与文字回退能力，优先定制“腿了个腿”的品牌字形，再形成强度有别的主题招牌、阶段标题和固定主行动字形。当前图片字有描边和阴影，但字形个性、字组轮廓与节奏仍需与立体动物一起定稿；不能因资源已经接入就直接判为完成。美术字可由字体、矢量或图片承载，普通功能标题、数值与正文保持分级 Label。不把文字图片化作为可读性修复的前置条件，不将所有文字烘焙进整张面板。数字、状态、用户数据、教学句和长正文继续使用文本。

### 制作与接入约束

1. 先确定品牌及展示字的职责、字形和文案，再选择字体、矢量或透明 PNG 等适合的载体。使用已确认授权的字体或原创字形；不依赖生成图像直接输出准确汉字。
2. 文字图保留实际宽高比和安全留白，按最终逻辑尺寸及目标设备像素密度制作；提供高分辨率源稿，不在运行时非等比拉伸。
3. 资源命名使用语义 key，例如 title-zoo、title-settings、action-start、action-continue；每项记录尺寸与用途。数量、角标和状态不烘焙。
4. 将不规则文字矩形加入独立图集或使用 Creator 管理的 SpriteFrame；不要改坏现有 ui-atlas 与 animal-cutouts 的切片契约。具体打包方式以导入和微信构建验证为准。
5. 图片字子节点只承担展示，按钮父节点继续拥有完整触摸区域、交互状态和语义名称。禁用、按下与处理中状态由按钮控制，避免每种状态重复制作整图。
6. 图片异步加载时预留尺寸，保证入口始终可辨识、布局不跳动；验证加载失败提示。采用图片字的节点不再重复叠加同一份 Label；保留必要的加载失败文字回退，加载成功后隐藏同字面回退层。
7. 优先定稿品牌展示字，再按各自职责处理主题招牌、情绪标题和固定主行动；通用文字、按钮布局与状态同步修正，数值和正文不套同等美术强度。不得宣称图片字天然更快或更省内存，需构建和设备实测。

## 页面修改方案

01—11 文件名仅用于定位对应页面，旧截图不代表全部当前实现。启动页以 start-ui-iphone/short、首页以 home-review-r2-long 与 short 系列画面结合当前代码判断；截图保存在本地 logs，不作为正式资产或接口事实。

### 01-start.png：启动页

现状：已具备独立品牌字、三只动物、乌龟进度、加载与连接阶段说明、失败重试，正式配置可连接时自动进入首页。仍沿用通用绿亮面木按钮；startText() 给状态、口号和底部辅助字统一描边，部分字号换算后仅约 10—12 逻辑像素。

方案：保留品牌资源接入、动物和进度的分层结构，优先调整品牌字形自身的圆润轮廓、弹性节奏和适度质感，与三动物共同形成主视觉；副标题保持功能排版。去掉功能字白描边，加载说明使用不透明奶油底与 14 逻辑字号；失败时同一区域展示原因，重试采用深绿实心底、完整点击区及可见处理中状态。资源按实际完成阶段推进，连接等待不伪装成已成功。调试入口仅在调试条件下展示，降低视觉重量；正式配置失败只显示真实原因与重试。底部正式提示与适龄信息按最终发布要求安排，不用一条小字占位视为完成。

验收：资源失败、登录失败、连接等待、重试成功、品牌图加载失败均可辨认；短屏与刘海屏不遮挡主要内容，失败与重试不导致布局跳动。对应 showStart()、prepareStart()、connect() 与安全区换算。

### 02-home.png：首页

#### 当前状态与保留项

当前 home-view.ts 已移除大木牌和围栏，具备本周摘要、实色动物场景、名称次数标签、分页、深绿主按钮与浅底次导航。home-animal-detail.ts 已有不带熊猫的动物只读详情，支持完整名称滚动。保留现有内容分区、可读性与数量规则，继续调整中心场景的边界和主体比例。

动物区的主要修改是让地形、动物站位和阴影形成自然场景。少量动物时通过适当尺度与组合关系建立重心，分页较多时保留稳定槽位与阅读秩序；不以填满空间为目标，也不把当前大圆角浅色容器直接作为最终美术外观。

剩余调整：本周摘要仍调用 showNotice()，会从简洁首页进入大熊猫通用面板，改为同样简洁的只读详情；领取成功目前只显示文字，改为展示实际领取的那一只动物。保留领取与挑战的固定占位。最新长屏截图右上设置与胶囊有相贴或重叠观感，虽代码已读取胶囊 bottom，仍须对照实际系统矩形复测并调整，不能只凭布局公式判为通过。分页箭头保留点按入口，轻扫只在动物场景识别，不由整个首页 root 响应以免与纵向滚动或底部导航争抢。

#### 目标构图

阅读顺序固定为简洁页头 → 本周收集信息 → 动物主场景 → 开始/继续挑战 → 图鉴/榜单/分享。动物是收集成果，主场景不是带框的图标列表。

下文动物场景的矩形宽高用于内容预算与点击布局，不要求外观呈现完整矩形面板。美术边界以地形与环境衔接为目标；信息区和名称标签仍使用稳定承托。

- 保持实色信息区内的标题，最多配 24 逻辑像素叶片，不恢复巨型木牌或厚标题边框。
- 不恢复完整前景围栏。木质风格保留在主按钮细边或远处两侧装饰，不能穿过动物与名字；可见描边不超过 2 逻辑像素。
- 背包独立承载储备信息，不在开始按钮上方重复列三种储备。
- 保持一条浅奶油底的次导航，不恢复三个方形木按钮。图标 24 逻辑像素、文字 14 逻辑像素、单入口触摸区域至少 88×44，按下时轻微变色。
- 中心以 `#e5f0d2` 为浅草地基调，使用低对比地形、柔和明暗和与外围相衔接的场景边界，避免一整块规则圆角容器主导画面。名称、次数仍落在不透明稳定底上，不叠花草纹理；动物完整不透明，阴影不与文字重叠。场景美术改变后重查前景分离与整体色调。
- 主按钮宽度约为内容宽度的 86%，高度 56 逻辑像素；次导航总高度 44，前后均留白。次导航虽横向总宽较大，但没有实心高饱和底、厚边和大图标，不能在视觉重量上压过主按钮。

#### 布局尺寸草案与坐标约定

以下尺寸均为微信视口逻辑像素，原点位于左上角，不是桌面截图像素或 Cocos fontSize。页面横向边距 16，内容宽为视口宽减 32；页头内左右触摸区分别为背包 112×44、设置 44×44。

当前设计宽 750、FIXED_WIDTH。比例 `s = 750 / viewportLogicalWidth`，逻辑长度乘 s 后用于 Cocos 布局；字体逻辑字号同样乘 s，不直接把 14 写成 Cocos fontSize。390 宽对应 s≈1.923，375 宽对应 s=2。局部内容中心 `(x,y)` 换为居中画布坐标时，使用 `(x-W/2, H/2-y)×s`，H 取实际逻辑视口高度，与 `view.getVisibleSize()` 核对。

`sys.getSafeAreaRect(false)` 已返回设计单位，不能再次乘 s。微信胶囊矩形属于逻辑坐标，转换一次。页头起点 `headerTop = max(safeTop + 8, capsuleBottom + 12)`，底部内容不得超过 `H-safeBottom-16`。下表是指定安全区输入下的草案，真实设备以运行时测量为准；不硬编码胶囊矩形。

顶部总只数与每只动物的次数标签复用同一数量显示规则，但分别按自己的最终字体和可用宽度测量完整文本：常见范围直接显示，超宽时按万/亿单位向下截断并缩写、必要时去除小数；仍超宽则显示可放入的明确下界短摘要，例如“≥1亿”，不使用无单位省略号、不SHRINK，也不让数量撑出槽位。代表例子为“12只”“1.2万只”“≥1亿只”；精确整数在已有信息区/动物详情弹层展示。动物次数标签宽为槽宽103/108减左右各6内边距，即91/96，字号14、lineHeight=18；缩写时必须包含“只”并把它计入宽度。顶部统计仍按139/154文字宽另测，不把同一缩写字符串盲目用于所有位置。数值来源和精确值不改变，不新增极端数值专用业务分支。

名字与次数在动物脚下独立的浅奶油小标签中，不铺整张卡片框。辅助文字通过字号和字重降低层级，不以低对比换取弱化效果。不批量使用白描边；品牌图片字如有描边，按单独美术资源处理。

上述四对不透明 sRGB 实色按相对亮度公式计算的对比值分别约为9.40、10.83、6.00、7.16，仅证明这些色值组合的数学对比。带透明度、纹理、渐变、高光、抗锯齿、图片字边缘的最终画面不继承该结果。制作后必须在文字覆盖区域检查背景最亮/最暗位置，并以实际手机大小、普通亮度肉眼检查；桌面放大截图不构成可读性验收。所有状态（按下、禁用、处理中）另查，不能声称当前首页已达标。

#### 数量、动物排布与溢出

数据源为 `zoo.items: AnimalCount[]`：每项对应一个动物种类及其本周 `receivedCount`。总只数为所有项的 receivedCount 之和，种数为有效不同 animal.id 数。顶部主统计写“已领取 N 只”，本周范围由标题和日期表达；精确只数与“K种动物”可在信息区详情查看；不能把 items.length 当成只数，也不渲染N只重复动物。若重复 id 出现，按接口异常处理或明确聚合规则，不静默重复显示。

场景每页使用相同的稳定槽位，翻页不改变动物属性或数据。分页只操作同一份 zoo.items，不访问永久图鉴冒充本周广场。首页每次刷新保持仍有效的页码，页数减少时回到最后有效页。默认沿用响应顺序，不自行发明稀有度或领取时间排序。

| -------- | ------------------------------------------------------ | ------------------------------------------------------- |
| 0        | 无占位假动物；中心一幅淡脚印及“通关后，带动物朋友回家” | 同左；仍使用下方唯一开始/继续按钮，不在空状态另加大按钮 |

每个槽位横向独立：场景左右内边距8，列间距9，三列等宽，343宽时每列 `(343-16-18)/3=103`，358宽时每列108。动物框按contain保持比例，动画与阴影必须在预留绘制区内裁限；不允许默认无限放大弹跳。

一排基础槽预算：动物88高、上下各4共8的阴影/动效余量，绘制区共96；动物与名字间4；名字字号14、显式lineHeight=18、两行固定36；名字与次数间2；次数14号、lineHeight=18。单槽总高 `96+4+36+2+18=156`。场景上下各8，分页前间距8，分页触摸区44：一排最小高度 `8+156+8+44+8=224`。两排在两行槽之间增加8：最小高度 `8+156×2+8+8+44+8=388`。名字保留两行高度，即使只有一行也不挤动次数或分页。明确设置行高，不沿用label()的默认1.25系数。

两排模式仅1—3种时可以使用96×120动物框，仍加上下各4绘制余量，单槽188，连同边距与分页共256，低于388；名称基线对齐，动画只在预留4像素内上下移动，阴影也不能越界。一排模式始终使用基础156槽，不因第一页种数少而放大，避免翻页跳动。两排模式末页不足4种仍保持两排槽位置，不切换成大动物模式；大动物只适用于本周总种数<=3。

动物缩放保持比例，按展示框 contain，不以贴图透明边界作为视觉大小。名称14逻辑像素、lineHeight=18，最多两行，超过以省略号显示；点击该动物展示本周该种的大图、完整名称与收到次数的只读弹层。次数只用 `receivedCount`，按统一数量规则在91/96内宽展示，精确数在该动物详情查看，不写未提供的总解锁数。动物与名字、次数标签作为一个可点单元；名字使用轻量下划线，按下时标签变深浅奶油色并给动物短暂亮度反馈，不额外放大出槽。统一44高分页区中央采用两行14号、lineHeight=18、行间2共38高，分别显示页码和“点动物查看详情”，上下各3；不增加场景高度。分页底部左右各44×44触摸区、中心页码；支持轻扫但不自动轮播。即使只有一页，也保留分页空间而隐藏箭头，避免领取新种类导致场景整体跳动。动物和标签均绘制在背景装饰之上，不再创建覆盖其上的围栏节点。

#### 挑战与领取状态

主按钮事实来源为 `active.run`。为空时写“开始挑战”；非空时沿用当前恢复行为。ACTIVE 可从 `level`、`questionIndex`、`questions.length` 显示“第2关 · 第3/12题”，题序以快照为准并限制在有效范围；LEVEL_1_PASSED 显示“教学已完成 · 进入第二关”，不显示“第4/3题”。对其他状态按实际恢复/结算流程处理，不推断剩余时间、胜率或奖励。点击后锁定该次操作，处理中显示文字，不仅降低透明度；不能在继续挑战时调用 start 新开局。

待领取资格目前来自 `animalClaimRun`，由已确认结算的 `animalClaimAvailable` 建立；`zoo()`、`active()`、`inventory()` 没有可恢复的资格列表，不能仅因本周0只就显示领取。冷启动恢复未领取权益是当前消费链路的缺口，本轮不承诺已解决，也不虚构接口字段。

有真实资格时，保留区显示奶油底、1逻辑像素暖金边，固定48高。左右内边距各12，右侧领取触摸区64×44、上下各2；与左侧文字间距8。343/358宽时左文案宽分别为 `343-24-64-8=247`、262。文案固定两行“有一位动物朋友”/“等你领取”，16号、显式lineHeight=20，总40高、上下各4；第一行7字，按全宽112预算，可放入247。这里的12像素内边距已包含边线，不再额外扣边框。右侧“领取”16号，lineHeight=20，在64×44内居中。无需红色角标、跳动、第二个绿色大按钮；该条有独立可见面积和留白，层级低于主按钮但不能缩成角标。处理中和错误文案仍使用这个文字区域，最多两行，超长错误转详情弹层，不能扩大高度挤动按钮。

领取中保持条目占位并锁定重复点击，文字变为“正在确认领取”；收到成功结果后展示这一只动物的反馈，再按 zoo 返回刷新只数和场景。请求结果未知时保留相同runId用于重试，不提前清资格或增加数字。已确认领奖但后续首页刷新失败时提示“已领取，动物园刷新失败”并重试读取，不伪装成领取失败再次发起新资格。无资格时不出现领取入口。通关奖励与普通分享仍遵循原有事实边界。

### 11-level-2.png：第二关

现状：牌堆与背景争夺注意力，数字密集。mahjong() 只按 open 改变底板，没有同步压低遮挡牌的动物和文字；牌面字号上限为 27 设计单位，在 375 逻辑宽时至多 13.5 逻辑像素，卡槽约 11.25、暂存牌约 10.5，部分信息还会 SHRINK。目标与卡槽统计分别放置，当前仅显示已选总量，没有与目标并列对照。

方案：压缩顶部木牌与空提示，把空间分配给棋盘，在低细节浅色区域呈现牌堆。可取牌保留清楚的边缘和两个属性，被覆盖牌的底色、动物与文字共同降低视觉重量，保留真实层叠及已露出的关系；点击受阻只在该牌局部说明“被覆盖”，不只晃动。

当前题拆为眼睛、腿数两组，卡槽统计采用同序的已选/目标；下一题保持次级但可读。牌面数字以 14—16 逻辑像素起评，明确乘 s 换为设计单位，不再混用 pt。卡槽与暂存牌可将属性改成上下两行图标加数字，缩减动物图占比，避免四个全宽字挤在一行；尺寸仍不足时调整布局，不省略属性、不扩大命中区跨牌。高对比辅助线索区分选中、可取、受阻，不只靠红绿颜色。

布局继续选择横排/竖排分离牌堆，保留每堆内部相对位置与覆盖关系，不为美观摊开牌。暂存区已有有界滚动，应保留并扩大其有效行高和说明空间；区分可复位与等待底牌，七格卡槽始终可见。可用棋盘高度不足时先重新预算顶部与辅助区，不能用 Math.max(280, ...) 把棋盘强行撑入其他区域。卡槽到六格时用稳定文字提醒，不反复闪烁或提前判负。道具图标、名称、数量分层，零库存查看说明，视频不可用时显示真实原因。

## 实施顺序与验收

### 第一批 先定整屏方向并修正核心操作

先按整体结论确定首页、对局、功能弹层与结果的构图、主体比例及材质强度，形成可比较的整屏方案；首页中心由规则容器表达转为自然草地场景。随后调整通用 label/button/overlay、逻辑尺寸与胶囊避让，完成第二关牌面、卡槽双指标、图鉴裁切和教学完成闭环。修正参考稿的目标、道具名和领奖含义；保留首页内容组织、分页和启动进度，不重复制作。

交付条件：各类整屏有明确重心与协调风格；目标、可取牌和两个属性可读；主要按钮满足逻辑点击区，不重叠或穿透；首末条内容可到达；教学过关、第二关加载失败均有明确去向。操作正确性问题同步处理，不因等待美术定稿而搁置。

### 第二批 补全状态与业务内容

完成设置、背包、图鉴、榜单的内容组织，补齐首页统计详情、实际动物领取结果、结算与道具选择状态。请求处理可见，未知结果保留原操作，动画期间相关输入保持锁定。

交付条件：加载、空数据、失败、待确认与成功可区分；不重复领奖或重开对局，不把取消表现成成功；弹层切换维持一次一层，模态期间有效计时暂停、关闭后恢复。

### 第三批 调整演出与资源

按已确定的布局控制入槽、消除、复位和庆祝范围，补轻量动物动作，复测微信端性能；按已定稿字形选择合适的文字资源载体。以现有品牌接入能力为基础验证比例、状态与回退，不用新增图片字数量衡量完成度。

交付条件：特效不盖数字与正文，减少装饰后信息完整；切后台、退出与恢复不残留输入锁、不补播奖励演出，资源按比例显示且失败有可辨识回退。

### 整体复核要求

逐项修改后，以相同视口和可比较状态复看整屏：动物园是否有场景与收集趣味，游戏页是否让棋盘成为主体，功能面板是否内容清楚且保留主题细节，结果演出是否有层次。再把相邻页面放在一起检查色彩、轮廓、字体与材质是否协调。

同时检查少量与大量内容，以及静止、过渡和关键反馈；避免只挑一张空态或一帧无粒子的画面。合并造成同一整体问题的修改，保护已经有效的主次关系。新版画面与运行证据形成后才判断改善结果，当前仅定义复核计划。
