# 开发与验收

版本：v2.0 · 2026-11-02 · 实施建议与验收基线，无功能完成声明。

## 1. 推荐实施顺序

1. 固化动物字典与玩法状态机，实现本地教学和判定；用小规模例子验证。
2. 实现版本化反向铺牌、多山峰与预设解回放；再扩到80–120张和12层。
3. 实现后台开局、玩家状态、幂等结算、图鉴、动物园、道具与额度。
4. 完成微信身份、分享和激励视频真机验证；依据验证结果接入领取，不伪造成功。
5. 联调开放数据域本周/历史榜、自己的数据重试同步。
6. 实现首版管理端、指标与周归档；事件冷归档完成验证后才启用删除。
7. 整理资源、动效、包体、性能、弱网和完整体验版验收。

## 2. 玩法验收

| 场景 | 预期 |
|---|---|
| 8眼16腿，四张2眼4腿入槽 | 整槽消除并切下一题 |
| 槽内仅子集匹配 | 不消除 |
| 眼睛或腿超过目标但未满槽 | 不失败，仍可操作道具 |
| 第7张恰好匹配 | 先消除，不判失败 |
| 第7张不匹配 | 立即失败，不能再用道具 |
| 部分露出的牌 | 不可点击 |
| 零腿牌 | 眼睛计入、腿贡献0，正常匹配 |
| 采用非预设合法组合 | 允许消除，即使导致以后无解 |
| 暂存仍有牌 | 不能宣告胜利 |
| 洗牌 | 仅牌区改变，种类/数量不变，不承诺恢复有解 |
| 多山峰开局 | 逐步回放预设答案时每张牌均可合法拾取 |
| 失败/胜利后再挑战 | 必须重新经过第一关 |

## 3. 道具与业务验收

- 每种局内和局外各最多1个；优先局内；第一关均禁用。
- 视频三种合计10次，分享每种1次；用完可再看视频，未用不能叠加。
- 移除反复追加超过12张，多行滚动可正确选牌；撤回返回正确来源。
- 取消/失败不扣额度；重复回调和超时重试只发一次。
- 每次正常胜负只有一次结算领奖机会，与局内额度独立；离开失效；主动放弃无机会。
- 首页成功领取每天最多3次，全满不发、取消不扣。
- 胜利解锁消除过的全部种类，随机奖励仅来自本局；重复动物当前数量增加、首页仍一只。
- 两设备并发领取不会超过库存和额度；重复结算不重复增加历史/周通关。
- 周日开局周一结算记新周；结算响应丢失后重试仍归首次结算所在周。
- 周归档失败不删除原记录，重跑不翻倍；图鉴/历史通关/储备不随周清空。

## 4. 后台与统计

建议首版页面：登录及改密、概览、用户进度、配置、管理员、审计。仅super管理账号和高风险配置；ops只能访问授权数据，菜单隐藏不是鉴权。

指标统一明确时间字段、去重键和分母：正式关通过率按已结束正式局计算，胜/负/放弃分别展示；分难度及配置版本。视频展示、完整观看、成功发奖分开。永久通关从业务表读取，不从90天事件推算。

D7建议按上海时区回流后第7个自然日，完整观察窗口结束才定0/1；未成熟样本不进入分母。新增归因采用固定规则且同一新用户只计一次；分享发起量不能从回流表推导。比率汇总用汇总分子/汇总分母，零分母返回空值。

## 5. 运维验收

- 身份入口拒绝伪造头、越权局ID和缺失身份；敏感日志脱敏。
- 登录锁定持久化，多实例一致；登出/重置/停用会话失效，最后super保护有效。
- 配置并发更新冲突可见，已有局不受新配置影响。
- 定时任务有租约、恢复与补跑，重复任务结果不翻倍。
- 冷归档积压大于5万行时，删除集合严格包含于校验上传集合；批次对象不覆盖。
- 备份恢复演练、迁移回滚方案、资源加载失败、广告中断、榜单写失败均有可复现验证。
