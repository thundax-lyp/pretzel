# 玩法与关卡生成

版本：v2.0 · 2026-11-02

## 1. 卡牌体系（已确认设计方向）

首版眼睛数 1/2/3/4；腿数 0/1/2/3/4/6/8，共 28 种可用属性组合，不要求每局全部出现。普通双眼动物为主，其他采用明确卡通形象。所有组合均可参与求和，不设不可消除的奇数腿垃圾牌。

| 腿数 | 形象方向 | 属性示例 |
|---|---|---|
| 0 | 蛇、漂浮果冻怪 | 1眼0腿、2眼0腿 |
| 1 | 单脚跳跳怪 | 2眼1腿、3眼1腿 |
| 2 | 小鸟、企鹅怪 | 2眼2腿、4眼2腿 |
| 3 | 三脚怪、金蟾 | 3眼3腿、2眼3腿 |
| 4 | 熊猫、狐狸及卡通变体 | 2眼4腿、3眼4腿 |
| 6 | 六足虫、甲虫怪 | 1眼6腿、4眼6腿 |
| 8 | 蜘蛛、章鱼怪 | 2眼8腿、4眼8腿 |

动物字典需提供 animal_id、名称、eyes、legs、卡图、首页动画、图鉴文案。图上属性要清晰可辨，角标辅助展示数字。变体是游戏属性，不把游戏化设定写成自然科普事实。

## 2. 判定与操作

对卡槽内所有牌求和：`sum(eyes)==target_eyes && sum(legs)==target_legs`。每次入槽完成后先匹配消除，再检查七格满槽失败。零腿卡仍贡献眼睛数。

消除整槽，不按答案组限制卡牌。题目始终按开局顺序推进。题目完成但还有牌、或牌已清空但仍有题目均不符合正常胜利条件，应作为生成/执行异常记录，不静默奖励。

- 点击：仅完全没有上层覆盖的牌可选。实施建议：有正面积交叠即覆盖，边缘相接不算覆盖；统一坐标系、牌尺寸和层序。
- 移除：将槽内全部牌追加暂存区，空槽不可使用且不消耗。暂存牌点击回槽也触发同样判定。
- 撤回：只撤回最近一次未触发消除的入槽，将牌返回其原牌区或暂存区。
- 洗牌：只重排牌区未消除牌，种类和数量不变，槽与暂存区不动，不保证恢复可解性。
- 实施建议：消除/洗牌后清除旧撤回记录；移动动画期间串行处理输入。暂存滚动与点牌需区分手势。

## 3. 关卡生成

已确认：题目及顺序开局确定；每题预设答案以 2–6 张为主，少量 7 张；从最后一题的答案开始自底向上铺，第一题答案最后铺在上层。允许多山峰，最高 12 层。初始必须存在通关路径。

实施建议的数据分工：后台决定局 ID、规则/配置/生成器版本、随机种子、动物实例及预设答案分组、题目顺序、布局参数；前端生成实际位置与遮挡。后台参数不能仅为无约束随机数，前端不能修改题目目标。具体字段见接口文档。

建议流程：
1. 选难度和数量 N，将全部 N 张分配到答案组；每组 2–7 张，总和精确等于 N，无冗余垃圾牌。
2. 计算每组目标眼睛/腿数，排列题目顺序，允许相同目标重复。
3. 逆序把答案组铺入多个山峰，控制重叠和层数。
4. 按真实点击、槽容量、题目顺序回放预设答案；不仅检查属性和，还检查每一步牌是否完全未覆盖。
5. 有限次重试，仍失败则重新请求或提示错误；不得展示未经初始可解性验证的布局。

实施建议：预设通关路径不依赖任何道具或广告。前后端共用版本化生成规则，保存种子和生成输入便于复现；不要求后台传每张牌的最终坐标。

## 4. 规模与难度

已确认正式关 80–120 张、最多 12 层。实施建议教学关沿用 30 张、最多 3 层，先用双眼、0/2/4 腿的易辨识组合；教学仍使用同样求和规则。

难度建议由牌数、层数、山峰数、可见分支、每题答案长度、属性复杂度及误配可能性共同控制。旧版公式和 85%/50%/20% 通过率均未验证，不作为验收保证。配置在开局固定，运营修改只影响新局。初始有解不等于真人必过；其他合法组合造成无解无需自动救场。

金蟾概率、特殊透层动效属于历史候选参数，尚未在本轮逐项确认；见决策记录。隐藏题机制不作为首版必需。
