# 架构与数据设计

版本：v2.0 · 2026-11-02 · 本文为实施建议，表名及字段待工程落地时固化。

## 1. 边界

小游戏主域负责渲染、确定性布局生成、交互、当地玩法状态和自己的榜单数据同步；开放数据域负责好友数据读取、排序与渲染。后台负责用户、生成输入、额度、库存、结算、收集进度、运营配置和统计。后台不保存好友关系，不接收好友名单。

推荐基础架构：原生微信小程序客户端、Java 21 + Spring Boot DDD后端、MySQL、定时任务、React + Ant Design + TypeScript管理端；微信云托管为候选部署方案。版本、平台能力、定时触发和身份注入链路均需验证。首版不强制引入Redis或消息队列。

## 2. 建议业务实体

| 实体 | 关键内容与约束 |
|---|---|
| user | 平台用户ID、资料、注册/活跃时间、首次来源 |
| player_progress | user_id唯一；永久通关数、版本；永久计数不从短期事件重算 |
| player_week_progress | user_id+week_id唯一；本周通关数和达成时间；支持跨周迟到重试 |
| animal_catalog | 稳定animal_id、eyes、legs、资源、文案；可使用版本化静态配置 |
| player_collection | user_id+animal_id唯一；首次解锁时间，永久保存 |
| player_animal_current | user_id+week_id+animal_id唯一；当周获得数 |
| player_animal_archive | 相同周粒度；历史获得数及归档批次，不混入当前周 |
| item_reserve | user_id+item_type唯一；数量0/1及版本，跨局 |
| game_match | match_id、归属、版本、种子、生成输入/摘要、难度、状态、结算时间、结果 |
| match_item | match_id+item_type唯一；局内库存0/1、分享已领次数、使用次数 |
| reward_operation | reward_op_id唯一；来源、归属局、道具、状态、首次响应、证据摘要；防重复发奖 |
| daily_reward_quota | user_id+date唯一；首页成功领取数0–3 |
| event_log | event_id唯一、用户、match_id、事件、props、客户端/服务端时间 |
| share_link / share_attribution | 不透明分享ID、分享者、场景、有效期与回流，新增归因规则固定 |
| game_config | schema约束配置、显式递增版本、更新人与时间 |
| stats_daily | 按日/难度等维度的已定义统计，可重算 |
| admin_user / admin_session | 角色、密码哈希、锁定、强制改密、会话撤销 |
| admin_audit_log | 操作者可为空以记录未知账号登录失败；写操作前后值 |
| job_run | 任务名+业务日期/批次、状态、租约、进度和错误 |

不固定为旧版7张表，可适当合并为JSON，但不能牺牲唯一约束、事务和并发安全。平台ID和业务ID使用区分大小写的存储/比较策略。

## 3. 状态与结算

建议正式局状态：created → playing → won/lost/abandoned/expired；终态不可反复切换。教学关事件与正式局区分；只有won触发胜利收益。结果首次提交时记录服务端结算时间，幂等重试不改变其周次。

胜利事务：锁定对局并检查归属和终态 → 周/历史通关数各+1 → 解锁本局消除动物 → 从这些动物种类中随机抽取奖励并增加当周获得数 → 保存首次结算响应及结果领奖机会 → 提交。

失败只关闭局、清空局内库存并开放一次结算领奖；放弃不开放。随机抽取只在首次结算发生，重试返回同一只动物。MVP可靠结算不代表胜负真实性已被强验证；必须检查归属、规则版本、合理数量和合法状态，后续可加操作回放。

局内领道具锁定对局/库存，原子检查三种视频合计额度、该种分享额度及库存；奖励操作幂等。客户端不得自行修改后台库存和次数。

## 4. 周切换与归档

统一Asia/Shanghai自然周，使用周一日期作为week_id；按服务端首次成功结算时间归周。读取当前动物园仅查询本周，不依赖任务恰好在零点完成。

归档按旧week_id批次复制并校验，唯一键保证重试不重复累加；只删除已成功归档的原记录。归档和并发结算使用明确切换/锁策略，避免复制后仍有旧周增量。永久图鉴、历史通关数和局外道具不清空。

事件冷归档可沿用90天候选保留期，但必须每批固定ID范围、记录行数/校验和、唯一对象名；上传验证成功后仅删本批ID，不允许上传5万行后删除全部过期记录。归档上线前不启用自动删除。

## 5. 配置、身份和后台

难度配置为版本化完整对象：牌数、层数、山峰、答案长度、属性分布等；后台校验可行性，开局固定版本。不能用MAX(updated_at)替代可靠配置版本。并发修改使用期望版本检查。

身份只信任验证过的微信接入链路，拒绝缺失身份和不可信公网伪造头。admin-api独立鉴权与访问限制；应用账号仅DML，迁移账号负责DDL。密码哈希、失败锁定、会话撤销和最后一个可用super保护均落实服务端。

好友榜建议使用weekly_wins/total_wins及week_id、achieved_at、revision；客户端重试同步时防旧响应覆盖新值。旧周数据按本周0处理。本人记录和跨设备同步需真机验证。签名升级延期，不能宣称当前榜单已防作弊。
