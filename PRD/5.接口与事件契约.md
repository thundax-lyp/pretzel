# 接口与事件契约

版本：v2.0 · 2026-11-02 · 以下为建议契约，不代表现存服务；实施前需固化字段schema及错误码。

## 1. 通用约定

游戏端前缀/api/v1，管理端/admin。响应为`{code,msg,data,trace_id}`。建议参数错误HTTP400、未认证401、越权403、冲突409、限流429、内部错误500；业务code与HTTP一致映射。ID作为字符串；时间ISO8601带时区；计数非负整数。分页`{list,total,page,page_size}`，默认20、最多100。

有业务副作用的请求使用稳定operation_id；重试同ID返回首次结果，同ID不同载荷报冲突。事件event_id与业务操作ID分开。仅对超时/暂时错误有限退避重试，不能靠重试生成新奖励。

## 2. 游戏端建议接口

| 方法与路径 | 用途和关键字段 |
|---|---|
| POST /session/init | 建档与初始化；返回服务端时间、周标识、配置版本、玩家进度、局外储备和首页额度 |
| GET /player/state | 刷新进度、图鉴、当周动物数量、储备和额度；历史动物归档默认不下发 |
| PUT /user/profile | 可选用户资料；头像上传来源和授权能力须按平台验证，不假定小程序组件可直接使用 |
| POST /match/start | 第一关通过后请求正式局；operation_id、client_rules_version；返回生成数据 |
| POST /match/{id}/finish | operation_id、result(won/lost/abandoned)、duration、摘要；幂等结算 |
| GET /match/{id}/result | 查询首次结算结果，解决响应丢失 |
| POST /rewards/prepare | source、match_id?、item_type?；检查资格后返回reward_op_id和下一步操作 |
| POST /rewards/{id}/claim | 提交平台结果证据；原子发放并返回库存、剩余额度 |
| GET /rewards/{id} | 查询发放状态及首次结果 |
| POST /match/{id}/items/use | operation_id、item_type；建议在线记录库存消费，客户端成功后应用效果；断线与补偿需实现一致性处理 |
| POST /share/create | 场景、关联局/领奖操作；返回不透明分享ID、文案、查询参数；不暴露明文用户ID |
| POST /report/batch | event_id、event、match_id?、props、ts；分析事件，不能发奖或加通关 |
| GET /config | 显式配置version；返回changed/configs，不把业务配置与客户端规则版本混用 |

道具在线消费可能影响弱网体验，是实施建议：正式实现必须处理“服务端扣成功但本地未应用”恢复，使用相同操作ID查询结果；不能以任意客户端失败回调直接退款。若改本地动作日志批量同步，需要单独确定防重复与一致性方案。

## 3. 开局与结算示例

```json
{
  "match_id":"m_001",
  "rules_version":"2",
  "generator_version":"1",
  "config_version":12,
  "seed":"seed_001",
  "difficulty":"MID",
  "card_total":90,
  "layout":{"max_layers":8,"peak_count":3},
  "cards":[{"card_id":"c1","animal_id":"panda_2e4l","eyes":2,"legs":4}],
  "questions":[{"question_id":"q1","target_eyes":8,"target_legs":16,"solution_card_ids":["c1","c2","c3","c4"]}],
  "limits":{"video_claims":10,"share_claims_per_item":1},
  "server_time":"2026-11-02T12:00:00+08:00"
}
```

示例数组为结构节选，不是完整90张可解关卡。cards总数必须等于card_total，所有牌恰好分配至一个预设答案组，分组求和精确匹配；题数不等于牌数。animal_id属性与版本化动物字典一致。前端生成坐标和遮挡后验证预设路径。

结算返回建议包含result、settled_at、week_id、weekly_wins、total_wins、new_collection_ids、awarded_animal、current_animal_count、result_reward_available及state_revision。放弃无领奖机会；失败无胜利收益。重复结算保持奖励与周次不变。

## 4. 事件字典建议

| 事件 | 关键属性 |
|---|---|
| app_launch | scene、launch_id、来源分享ID |
| tutorial_start / tutorial_end | challenge_id、result、duration |
| match_start / match_end | match_id、result、difficulty、config_version、duration、结束原因 |
| item_claim / item_use | item_type、source、reward_op_id/operation_id、槽占用 |
| ad_request / ad_show / ad_complete / ad_error | placement、reward_op_id、error；与实际发奖分开 |
| share_invoke / share_return / share_open | share_id、业务场景；return不表示分享成功 |
| collection_unlock | animal_id、match_id；建议由结算产生 |
| rank_show | weekly/history；仅本人交互，不上传好友资料 |
| progress_snapshot | 已消除数、牌区/槽/暂存数量；降采样 |

公共字段event_id、schema_version、用户身份(服务端注入)、客户端时间、服务端接收时间。建议单批最多20条、body16KB、props2KB；逐条返回accepted/rejected，去重事件不重复入库。队列有定时flush、退避、持久化和上限；不能把唯一结算结果丢在可淘汰队列里。

## 5. 管理接口范围

首版：登录/登出/改密、实时与趋势看板、用户与进度查询、配置版本管理、管理员管理、审计。后续：事件检索导出、分享归因分析、难度漏斗及任务补跑。账号停用/角色修改/密码重置即时撤销相应会话，所有修改与审计同事务。

配置写请求携带expected_version；只允许白名单键和schema。导出有范围、行数、频率限制并防CSV公式注入；不得把密钥、凭据或好友数据放入响应/日志。未定义的管理补偿功能不属于首版范围。
